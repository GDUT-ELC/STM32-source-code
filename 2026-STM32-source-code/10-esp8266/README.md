# 10-esp8266：WiFi 与 MQTT AT 指令工程

## 工程说明

使用 STM32F407VET6 的 UART5 向 ESP8266 发送 AT 指令，依次配置 STA、连接 WiFi 和 MQTT，并提供属性发布、回复主题订阅接口。当前主程序仅执行初始化指令序列，主循环为空。

## 使用方法

1. ESP8266 RX 接 PC12（UART5 TX），TX 接 PD2（UART5 RX），共地；使用符合模块要求、能承受无线发射峰值电流的稳定电源，串口逻辑为 3.3V。
2. 确认模块运行支持 MQTT 指令的 AT 固件，串口波特率为 115200、8N1，并按模块要求设置 EN、RST 和启动引脚。
3. 在 `Bsp/esp8266.h` 填写自己的 `WIFI_NAME`、`WIFI_PASSWORD`、`MQTT_CLIENT_ID`、`MQTT_USERNAME`、`MQTT_PASSWORD`。
4. 当前 MQTT 服务器在 `Bsp/esp8266.c` 中为 `mqtts.heclouds.com:1883`；按实际平台修改服务器、端口和认证参数。
5. 用 Keil MDK 打开 `MDK-ARM/10-esp8266.uvprojx`，编译、下载。确认联网后，按需调用 `esp8266_pub()` 发布属性或 `esp8266_sub()` 订阅回复主题，填写实际产品 ID、设备名和属性名。

## 使用注意

- 参数默认留空，使用前必须填写。ESP8266 通常连接 2.4GHz WiFi，确认热点频段、名称和密码匹配。
- **当前驱动只发送命令并固定延时，不解析 AT 回包。** `HAL_OK` 仅表示 MCU 串口发送成功，不能证明 WiFi 或 MQTT 已连接，也不会自动接收订阅消息。
- 用串口工具观察模块回包确认 `OK`、连接结果及错误原因，或参考 11-Demo 的回包状态机。网络较慢时固定等待时间可能不足，需要增加等待或改为按回包推进。
- 发布和订阅主题采用 OneNET 风格的 `$sys/.../thing/property/...` 路径；换平台时需同步修改主题、JSON 格式及认证方式。当前连接参数不启用 TLS，服务器要求加密时需调整固件配置和连接方案。
- AT 命令缓冲区为 200 字节，长账户、令牌或主题可能超长；接口报错时检查长度及特殊字符转义。不要在多个任务中同时调用共享发送缓冲。
